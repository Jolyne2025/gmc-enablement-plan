4. Decision Plans for the Three Data Gaps

A) availability (stock status)

Problem: wlw is an inquiry platform without real-time stock tracking. GMC requires in_stock / out_of_stock / preorder / backorder.

Recommended solution: set all active offers to in_stock uniformly

  • Rationale: offers that are published and not deleted can be treated as “sellable / inquiry-able”
  • Impact: simple and direct, no downside; if actually out of stock, the merchant replies after the buyer sends an inquiry
  • Risk: a very small number of discontinued-but-still-displayed offers may not reflect reality → can add supplier-flagged stock signals later

B) price format (range prices)

Problem: the DB stores price_min / price_max ranges; GMC requires a single fixed price.

Recommended solution: use price_min (supported by industry evidence + official requirements)

  • 82.9% of priced offers have only price_min (single value already), no extra handling needed
  • 49.1% of range offers have gap ≤ 1.5x, so using min deviates from the real price controllably
  • Industry evidence (2026-08-20, see 3.8): B2B platforms like Made-in-China submit and display the lowest price (min) in shopping channels, and the page JSON-LD also outputs min — feeding min matches the landing page exactly, zero mismatch risk; using max (MOQ-tier unit price) contradicts industry practice and inevitably mismatches
  • Official landing page requirement (see 3.9): “clearly show the product price” is met (re-check 2026-08-20: priced PDP UI already shows “ab min €”, no new dependency) — feeding min is three-way consistent with UI / JSON-LD; range offers show “min - max €” in the UI with min first and most prominent
  • Exception handling: the 20,769 offers with gap > 10x should be skipped (not uploaded) — the UI shows a min-max range; when the gap is too large, min deviates heavily from the actual deal price, hurting CTR and review perception (note: the earlier “inconsistent with page JSON-LD” rationale does not hold — JSON-LD outputs min, same as the feed)

C) link (product landing page URL)

Problem: data_external_url points to suppliers' external sites (e.g. https://supplier-shop.com/product/xyz); GMC requires the URL to be a PDP on a self-owned verified domain — we want to drive traffic to ourselves, not to merchant sites.

Recommended solution: construct wlw.de own PDP URLs (verified, see 3.6)

wlw.de PDP URL pattern: https://www.wlw.de/de/firma/{company_slug}-{company_slug_id}/produkte/{product_slug}-{product_slug_id}

  • Three elements: company slug_id (companies.slug_id, 100%) + company slug (slugify company name) + product slug_id (offers.slug_id, 100%)
  • Missing product slug (61%) is not blocking: ARISE-1239 (live 7/16) VCG read path falls back to slug_id; /produkte/{slug_id} verified HTTP 200
  • Company slug fault tolerance: wrong slug + correct slug_id verified HTTP 200 (slug_id is authoritative); only a completely missing company segment 404s
  • EP side (verified 2026-08-20): ep_products.prd_url is likewise a merchant external link and unusable; the EP own PDP URL pattern is verified: https://www.europages.fr/fr/company/{company_slug}-{company_slug_id}/products/{product_slug}-{product_slug_id} (same structure as wlw) — product segment can degrade to /products/{slug_id} (verified 200); company slug required (404 without it); frontend UI mirrors wlw (data-test="product-price", EUR display, range min first); all Phase-1 EP accounts (ep.it/es/fr) rely on this pattern; EP domains are assigned by target-sales-country site (country-site model, confirmed 2026-08-20: ep.XX lists offers sellable in that country; pool from all European countries, not only that country's companies); each EP account completes domain verification in its own GMC account (see 1. -- Priced wlw.de GMC-ready offers (incl. link construction elements)
SELECT so.id, so.data_name, so.data_description,
       so.data_price_min, so.data_price_cur,
       so.slug_id AS product_slug_id,  -- product slug_id (required for link, 100%)
       cc.slug_id AS company_slug_id,  -- company slug_id (required for link, 100%)
       cc.name AS company_name,        -- company slug = slugify(name)
       r.snapshot_slug AS product_slug -- product slug (39% have it; link uses pure slug_id when missing)
FROM supplier_offers.offers so
JOIN companies.companies cc ON so.supplier_id = cc.supplier_facts_uuid
LEFT JOIN (
  SELECT offer_id, snapshot_slug,
         ROW_NUMBER() OVER (PARTITION BY offer_id ORDER BY update_time DESC) rn
  FROM supplier_offers.revisions
) r ON r.offer_id = so.id AND r.rn = 1
WHERE so.delete_time IS NULL
  AND so.publish_time IS NOT NULL
  AND so.data_price_min IS NOT NULL AND so.data_price_min > 0
  AND cc.platform_wlw = true
  AND so.data_name IS NOT NULL AND LENGTH(so.data_name) <= 150
  AND so.data_description IS NOT NULL AND LENGTH(so.data_description) <= 5000
  AND EXISTS (SELECT 1 FROM supplier_offers.images si
              WHERE si.offer_data_images = so.id)
  AND (so.data_price_max IS NULL OR so.data_price_min = so.data_price_max)
  AND so.data_price_cur = 'EUR';

  • ⚠️ 非 EUR 币种换算风险（2026-08-20 新发现，含 GMC 货币规则查证）：wlw 带价品中 EUR 545,964（95.6%），非 EUR ≈ 25,344（4.4%，CHF 21,055 + GBP 3,803 + SEK 413 等）——UI 主价格区按汇率换算成 EUR 显示（实测 2.08 GBP → “2,43 €”），JSON-LD / 数据库为原币种；EP 三账号品池几乎全 EUR（Redshift 2026-08-20）：ep.fr 140,401/193（99.86%）、ep.es 80,652/14（99.98%）、ep.it 59,453/49（99.93%）→ 非 EUR 仅 ~256 个，且 ep.fr 前端实测默认 EUR 展示（PDP “16,00 €”、showroom “130,00 - 150,00 €”，与 wlw 同构含汇率机制）；推全新增非 EUR 原币品 ~129k（GB 55,008 GBP / PL 30,433 PLN / TR 14,989 TRL 等，占 EP 带价品 ~19%）——ep.co.uk 站实测：英国公司 BEE 4 LIMITED 的 Industrial Labels 库中 10 GBP → 前端 “from 11,69 €”（GBP→EUR 换算，与 wlw 同机制）→ 推全时非 EUR 原币品同样按前端汇率换算 EUR 提交（见 2.2 全量货币设置）。GMC 货币规则（官方）：① feed 的 price 必须含 ISO 4217 货币代码（[price] 属性 6324371）；② 金额与币种必须与落地页 / 结构化数据 / checkout 三方一致（产品数据规范 7052112 + mismatch 修复 9773429）——币种不一致 → price mismatch disapproval；③ 官方按 target country 列支持货币（160637），非目标国货币可经官方 Currency Conversion 换算支持（多 target country 见 14991840），但本地货币提交表现更优；④ 落地页按访客位置自动切换货币 + feed 固定货币 = mismatch 高危（官方自动换算限制 6150127，Shopify 社区实测：落地页自动货币换算须禁用）。wlw/EP 侧实证：页面货币选择器默认 EUR（2026-08-20 截图），URL 无货币参数（/de/、/fr/、/en/ 固定），非 EUR 原币品 UI 一律 EUR 换算展示（wlw 2.08 GBP → “2,43 €”；EP 10 GBP → “from 11,69 €”）→ 前端展示货币统一为 EUR。→ 结论：全量账号 feed 统一按 EUR 提交（非 EUR 原币按 wlw/EP 同口径汇率换算），与各站 UI 默认展示一致、符合三方一致规则；不建议原币提交（UI 展示 EUR → 币种必 mismatch）。待确认：货币选择器是否按访客地区自动变（若会，Google 爬虫可能抓到非默认货币版本，见 3.9 行动）
  • availability 审核结论（2026-08-20 补充）：① 会被审核——feed 层必填（已达标）+ 落地页层一致性检查：页面显示的实际库存状态与 feed 矛盾（页面“可加购”但 feed 标 out of stock，或页面“售罄”但 feed 标 in stock）→ mismatch disapproval（官方 Inaccurate availability status 文档 9773127 专项处理）；页面不显示库存状态 → 不构成 mismatch（与 price 同逻辑）；② UI 非硬性——Landing page requirements 只硬性要求价格 “clearly show”，未要求 UI 显示“有货”状态；但 UI 一旦显示任何库存状态（标签/按钮态），必须与 feed 一致，否则 mismatch；③ 2026-03-26 Google 更新 Landing page requirements（SERoundtable 报道）：“products can successfully be added to a cart and delivered to a customer”；“out of stock 商品落地页 Buy 按钮必须置灰”（隐藏/可点击均不允许）——对 wlw 询价制（无 Buy 按钮）强化了“不可直接购买”的实质风险（与 2.9 结论互相印证）；④ 结构化数据必须写且与 feed 一致：官方 price/availability mismatch 修复文档（9773429）明确要求 price 与 availability 与页面 schema markup 对齐——biz-seo-sdk 已输出 offers.availability=InStock，与 feed 统一 in_stock 吻合，无需新开发；⚠️ 反向约束：若未来上线缺货品，feed + JSON-LD + UI 三方必须同步改为真实状态，否则构成 Inaccurate availability 违规。

3.8 竞品调研：B2B 阶梯价在购物渠道的展示（2026-08-20）

背景：评估“区间价产品 feed 提交 min 还是 max”时，实际调研同类 B2B 平台（Made-in-China）在购物渠道的展示方式（Google Shopping 反爬 → Bing Shopping 实况 + 实站验证）。

验证项结果
Bing Shopping 搜索 “wholesale stainless steel tumbler”Made-in-China 批发产品全部显示单个最低价：$0.97 / $1.78 / $2.80 / $3.04 / $3.13 / $3.33 / $3.64 / $3.76 / $4.18 / $5.07（均为阶梯价最低档），无一显示 max 或区间
Made-in-China 产品页（cnyihi.en.made-in-china.com 实站）页面 UI 显示阶梯价表（US$3.14 / 2.86 / 2.72 / 2.57，MOQ 档最高、大批量最低——与 wlw 的 min/max 语义同构）；JSON-LD offers.price = “2.57”（= min），availability=InStock

3.9 PDP 价格展示合规（官方 Landing Page Requirements，2026-08-20 复核修正）

问题（2026-08-20 复核修正）：wlw PDP UI 是否满足官方 “clearly show the product price” 硬性要求？此前结论“UI 不渲染价格”已被 3.7 复核推翻——有价格品 UI 正常展示（“ab 119 €”等格式）。剩余合规风险：① 询价制“不可直接购买”② 非 EUR 币种 UI 换算 EUR 展示 vs feed 原币种。

来源要点
Google Merchant Center Help
About landing page requirements（官方文档 4752265）		“Clearly show the product price on the landing page. The price should be easy to view, and should match your product data. If your landing page has multiple prices, the price of the advertised product must be the most prominent.”
落地页必须清晰展示价格；多价格（如阶梯/区间）时，广告商品的价格必须最显眼

price 属性定义（6324371）“Submit an amount and currency that match the price on your landing page and the checkout pages”；变体价格场景：“different prices for each of these variants”（多规格多价可拆分为变体处理）

结论（复核后）：① 官方硬性要求已满足——wlw 有价格品 PDP UI 主价格区展示 “ab min €”（range 品显示 “min - max €”，min 在首位最显眼），符合 “clearly show” + “advertised product price must be the most prominent”；无价格品因数据库本身无价（64%），不涉及展示义务；② feed 用 min 与 UI / JSON-LD 三方一致（EUR 品实测 119=119、8212.5=8.212,50 €）→ price mismatch 风险极低；③ 询价制“不可直接购买”风险独立保留——官方要求 “products can successfully be added to a cart and delivered”（2026-03-26 更新）与论坛结论（107143830：无价格 + 不可直接购买 → 不能使用 GMC）依旧适用，这是本方案第一大风险（与 3.7 availability 结论互相印证）；④ ⚠️ 非 EUR 币种换算风险（新）——UI 将 CHF/GBP/SEK 等（~25.3k，4.4%）按汇率换算成 EUR 展示（实测 2.08 GBP → “2,43 €”），JSON-LD/数据库为原币；feed 需决定币种口径（见行动）。

4. 三大数据差距决策方案

A) availability（库存状态）

问题：wlw 是询价平台，无实时库存追踪。GMC 要求必填 in_stock / out_of_stock / preorder / backorder。

推荐方案：所有活跃 Offer 统一设为 in_stock

  • 原理：published 且未 delete 的 offer 可视为"可销售/可询价"状态
  • 影响：简单直接，无负面效果；如实际缺货用户发起询价后由商家回复
  • 风险：极少数已停产但仍保留展示的商品可能不符合实际情况 → 可后续增加 supplier 标记的库存状态信号

B) price 格式（区间价处理）

问题：数据库存储 price_min / price_max 区间，GMC 要求单一固定价格。

推荐方案：使用 price_min（行业实证 + 官方要求支撑）

  • 82.9% 有价格品只有 price_min（本身就是单值），无需额外处理
  • 区间价中 49.1% 的 gap 在 1.5x 以内，use min 与实际价格偏差可控
  • 行业实证（2026-08-20，见 3.8）：Made-in-China 等 B2B 平台在购物渠道提交并展示最低价（min），页面 JSON-LD 亦输出 min——feed 用 min 与落地页完全一致，零 mismatch 风险；用 max（MOQ 档单价）与行业实践相反且必然 mismatch
  • 官方落地页要求（见 3.9）：“clearly show the product price” 已满足（2026-08-20 复核：有价格品 PDP UI 已展示 “ab min €”，无需新增依赖）——feed 用 min 与 UI / JSON-LD 三方一致；range 品 UI 显示 “min - max €”，min 在首位最显眼
  • 例外处理：gap > 10x 的 20,769 个 offer 建议 skip（不上传）——UI 展示 min-max 范围价，gap 过大时 min 与实际成交价偏离大，影响点击转化与审核观感（注：此前“与页面 JSON-LD 不一致”的理由不成立——JSON-LD 即输出 min，与 feed 一致）

C) link（产品落地页 URL）

问题：data_external_url 指向供应商外部网站（如 https://supplier-shop.com/product/xyz），GMC 要求 URL 是自有已验证域名的 PDP——我们要给自己引流，不导流商家站。

推荐方案：构造 wlw.de 自有 PDP URL（已实测验证，见 3.6）

wlw.de PDP URL 模式：https://www.wlw.de/de/firma/{公司slug}-{公司slug_id}/produkte/{产品slug}-{产品slug_id}

  • 三要素：公司 slug_id（companies.slug_id，100%）+ 公司 slug（slugify 公司名）+ 产品 slug_id（offers.slug_id，100%）
  • 产品 slug 缺失（61%）不阻塞：ARISE-1239（7/16 已上线）VCG 读路径 fallback 返回 slug_id，/produkte/{slug_id} 实测 HTTP 200
  • 公司 slug 容错：错误 slug + 正确 slug_id 实测 HTTP 200（slug_id 为权威标识）；公司段完全缺失才 404
  • EP 侧（2026-08-20 实测确认）：ep_products.prd_url 同为商家外部链接不可用；EP 自有 PDP URL 模式已实测：https://www.europages.fr/fr/company/{公司slug}-{公司slug_id}/products/{产品slug}-{产品slug_id}（与 wlw 同构）——产品段可降级 /products/{slug_id}（实测 200）；公司段 slug 必需（无 slug 404）；前端 UI 与 wlw 同构（data-test="product-price"，EUR 展示，range min 首位）；第一期 3 个 EP 账号（ep.it/es/fr）均依赖该模式；EP 域名按目标销售国家站归属子域（国家站模式，2026-08-20 确认：ep.XX 收录可卖到该国的品，品池来自欧洲各国、非仅该国公司）；各 EP 账号在各自 GMC 账号完成域名验证（见 1. 前置依赖）
  • ⚠️ GMC 域名验证：wlw.de 需在 GMC 完成域名验证（UC-352 前置）

-- 带价品 wlw.de GMC Ready（含 link 构造要素）
SELECT so.id, so.data_name, so.data_description, 
       so.data_price_min, so.data_price_cur,
       so.slug_id AS product_slug_id,  -- 产品 slug_id（link 必需，100%）
       cc.slug_id AS company_slug_id,  -- 公司 slug_id（link 必需，100%）
       cc.name AS company_name,        -- 公司 slug = slugify(name)
       r.snapshot_slug AS product_slug -- 产品 slug（39% 有；缺失时 link 用纯 slug_id）
FROM supplier_offers.offers so
JOIN companies.companies cc ON so.supplier_id = cc.supplier_facts_uuid
LEFT JOIN (
  SELECT offer_id, snapshot_slug,
         ROW_NUMBER() OVER (PARTITION BY offer_id ORDER BY update_time DESC) rn
  FROM supplier_offers.revisions
) r ON r.offer_id = so.id AND r.rn = 1
WHERE so.delete_time IS NULL 
  AND so.publish_time IS NOT NULL
  AND so.data_price_min IS NOT NULL AND so.data_price_min > 0
  AND cc.platform_wlw = true
  AND so.data_name IS NOT NULL AND LENGTH(so.data_name) <= 150
  AND so.data_description IS NOT NULL AND LENGTH(so.data_description) <= 5000
  AND EXISTS (SELECT 1 FROM supplier_offers.images si 
              WHERE si.offer_data_images = so.id)
  AND (so.data_price_max IS NULL OR so.data_price_min = so.data_price_max)
  AND so.data_price_cur = 'EUR';
-- → ~389k (仅 EUR + 单值价格, 用于 MVP)

第一期域名分布 SQL（2026-08-20；第一期 = 仅 wlw.de）

-- 按域名账号切分（wlw=true 全部归 wlw.de；EP 按目标销售国家站归 ep.XX（收录可卖到该国的品，品池来自欧洲各国）；ep 仅计非 wlw 品避免重复）
SELECT CASE WHEN cc.platform_wlw THEN 'wlw.de'
            WHEN cc.country = 'FR' THEN 'ep.fr'
            WHEN cc.country = 'ES' THEN 'ep.es'
            WHEN cc.country = 'IT' THEN 'ep.it' END AS domain,
       so.data_price_kind, COUNT(*) AS n
FROM supplier_offers.offers so
JOIN companies.companies cc ON so.supplier_id = cc.supplier_facts_uuid
WHERE so.delete_time IS NULL AND so.publish_time IS NOT NULL
  AND so.data_price_min IS NOT NULL AND so.data_price_min > 0
  AND (cc.platform_wlw OR (cc.platform_ep AND cc.country IN ('FR','ES','IT')))
GROUP BY 1, 2;

-- 价格区间 gap 检查
SELECT so.id, so.data_price_min, so.data_price_max, 
       so.data_price_max / NULLIF(so.data_price_min, 0) AS price_ratio
FROM supplier_offers.offers so
WHERE so.delete_time IS NULL AND so.publish_time IS NOT NULL
  AND so.data_price_min IS NOT NULL AND so.data_price_min > 0

  AND so.data_price_min != so.data_price_max
  AND so.data_price_max / NULLIF(so.data_price_min, 0) > 10;
